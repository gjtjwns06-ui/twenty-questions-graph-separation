# VS Code에서 이어갈 스무고개 그래프 연구

## 목표

`Twenty_Questions_Paper_Draft.md`의 본실험을 구현한다. 대상별 속성 수와 전체 질문 쌍의 공동 출현 수가 같은 두 이분 지식그래프에서 최적 첫 질문과 식별 비용이 어떻게 달라지는지 조사한다. 그래프 생성 → 통제 교환 → 정확 계산 → ML 비교 → 수학적 구조 분석의 다섯 단계를 유지한다.

## 먼저 읽을 부분

- 논문 3–4절: 문제 가정, 비용 정의, 반드시 보존할 통계.
- 논문 5절: 실제로 검산한 14×8 예시와 현재 주장할 수 있는 범위.
- 논문 6절: 아직 실행하지 않은 본실험과 비교 방법.
- 논문 8–9절: 미완료 항목과 해석의 한계.

## 시작 순서

1. Python 3.10 이상의 별도 환경에서 `python verify_witness.py --output verification_recomputed.json`을 실행한다. 동봉한 `verification.json`의 핵심 수치와 대조한다. 이 단계는 작은 예시의 재현이며 본실험이 아니다.
2. 행렬, 교환 이력, 부모 ID, 통계 검사, 정확 비용을 보존하는 작은 파이프라인을 구현한다. 목표 대상은 균등 분포, 답은 정확한 이진값, 질문은 주어진 열로 제한한다.
3. 작은 예비실험으로 실행 시간, 메모리, 교환 수락률, 미완결률을 확인한다. 사용자 PC에서 가능한 규모를 선택하고 그 근거를 기록한다. 임의로 큰 데이터부터 생성하지 않는다.
4. 본실험의 생성 분포, 크기 범위, 독립 부모 수, 분할, 주 지표, 동점 처리, 특징과 모델 선택 범위를 설정 파일과 설계 문서로 고정한다. 예비 자료와 최종 시험 자료를 분리한다.
5. 통제 쌍과 정확 라벨을 생성한 뒤 비학습 기준선을 먼저 비교한다. 그다음 ML을 학습·검증하고 독립 시험을 평가한다. 원시 표에서 논문 표와 그림을 재생성한다.

## 꼭 지킬 해석

- 같은 부모의 교환본, 이름 순열, 후속 상태는 모두 같은 데이터 분할에 둔다. 같은 Gram 구조와 동형 세계의 분할 중복도 점검한다.
- 전체 Gram, 전체 이분 스펙트럼, 전체 C4·C6, 단순 삼중 빈도 히스토그램은 주 설정에서 고정된다. 이런 특징으로 쌍을 구별할 수 있다고 가정하지 않는다.
- 조건부 구조와 선행 탐색을 사용하되 정확 최적 비용 또는 시험 라벨을 입력 특징에 넣지 않는다. 질문 ID 자체도 특징으로 사용하지 않는다.
- 첫 질문의 초과 비용과 전체 정책의 실제 실행 비용을 분리한다. 최적 질문은 하나의 임의 ID가 아니라 argmin 집합으로 저장한다.
- ML이 이기지 않아도 결과를 보존한다. 큰 효과만 골라 빈도를 계산하거나 본실험 값을 예상하여 채우지 않는다.
- 정확 계산의 시간 초과는 미완결이다. 오답이나 근사 정답으로 바꾸지 않는다.
- 핵심 실험에는 LLM API가 필요 없다. 이 작업을 위해 API 키를 요청하거나 유료 호출을 자동으로 추가하지 않는다.

## 권장 산출물

실행법을 담은 README, 예비실험 보고서, 고정한 본실험 설정, 원본·파생 그래프와 계보, 통제 검사 결과, 정확 해법의 완료 기록, 첫 질문별 비용, 부모 단위 분할, 모델 및 특징 정의, 정책 비교표, 효과가 없는 사례를 포함한 구조 분석, 원시 자료에서 생성한 표·그림을 보존한다.

동봉한 코드는 검산 예시용이며 완성된 본실험 파이프라인이 아니다. 논문 초안의 실험 절을 읽고 구현해야 한다. 최종 논문은 실제 결과에 맞추어 개정한다.
